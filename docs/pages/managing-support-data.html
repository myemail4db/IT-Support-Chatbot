Managing Support Data

What you'll find here: How authorized maintainers can add approved support topics without routinely changing application code.

Design principle

Routine support-topic maintenance should be data-driven and should not require application development. Authorized IT support personnel, application-support analysts, knowledge-base owners, and developers can use this workflow.

Human review is required: AI accelerates formatting and integration guidance. It is not the source of truth and must not invent procedures, commands, URLs, security instructions, or company policies.

Current support topic structure

FieldPurpose
idUnique lowercase, hyphenated identifier.
category / subcategoryOrganizes the topic.
titleHuman-readable procedure title.
semantics.intentsWhat the user is trying to do.
semantics.objectsThe item, feature, system, or thing involved.
semantics.contextsThe application, environment, or setting.
semantics.statesRelevant condition or status; may be empty.
keywordsImportant words associated with the topic.
phrasesNatural ways users may describe the request.
solutionApproved support instructions.

Maintenance workflow

Approved IT procedure
        ↓
Use documented AI prompt
        ↓
Generate support-topic JSON
        ↓
Human review
        ↓
Check semantic vocabulary
        ↓
Add approved data
        ↓
Run test conversations
        ↓
Commit the change

Files to evaluate

  • data/support/support-data.json
  • data/semantics/intent-semantics.json
  • data/semantics/object-semantics.json
  • data/semantics/context-semantics.json
  • data/semantics/state-semantics.json

Reuse existing semantic values when they already represent the concept. Add new vocabulary only when necessary.

When a non-developer can make the change

A non-developer can use this workflow when the new problem fits the existing support-data and semantic structures. Ordinary knowledge-base maintenance should not require TypeScript changes.

When developer assistance is required

Stop if the request requires new chatbot behavior rather than new support knowledge, such as scoring changes, new conversation behavior, authentication, external integrations, or application logic.

Use the AI support topic prompt

Continue to AI Support Topic Prompt. It produces project-compatible JSON, an integration plan, plain-language instructions, review checks, and test questions.
