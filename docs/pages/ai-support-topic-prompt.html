AI Support Topic Prompt

What you'll find here: A reusable prompt that converts approved IT procedures into the project's support-data format and explains how to integrate and test the change.
Review before check-in: Generated information must be reviewed by an authorized person. If the change crosses from data maintenance into application development, involve a developer.

Prompt: Add a new support topic

Copy the complete prompt below and paste the approved IT support procedure at the bottom.

You are helping maintain an IT Support Chatbot knowledge base.

Convert APPROVED IT support documentation into the chatbot's existing support-data format and explain how to integrate it.

RULES
1. Use only the approved source material supplied.
2. Do not invent procedures, URLs, commands, policies, security instructions, application behavior, or troubleshooting steps.
3. If information is missing, write REVIEW REQUIRED instead of guessing.
4. Preserve the technical meaning and order of the approved procedure.
5. Routine support-topic maintenance is data-driven. Do not recommend changing application source code unless the request cannot be represented by the existing support-data and semantic structures.
6. Do not create new project files unless genuinely required.
7. If application source code must change, label it DEVELOPER ASSISTANCE REQUIRED.
8. Generated content must be reviewed before becoming approved chatbot knowledge.

CURRENT SUPPORT TOPIC SCHEMA
{
  "id": "lowercase-hyphenated-id",
  "category": "Category",
  "subcategory": "Subcategory",
  "title": "Human-readable title",
  "semantics": {
    "intents": ["VALUE"],
    "objects": ["VALUE"],
    "contexts": ["VALUE"],
    "states": []
  },
  "keywords": ["keyword"],
  "phrases": ["natural language phrase"],
  "solution": ["instruction line"]
}

SEMANTIC DIMENSIONS
- intents: what the user is trying to do
- objects: the item, feature, system, or thing involved
- contexts: application, environment, or relevant setting
- states: condition or status when applicable; may be empty

OUTPUT

SECTION 1 - SUPPORT TOPIC JSON
Return one valid JSON object matching the schema exactly. Use uppercase semantic values. Keep states as [] when no meaningful state is supported.

SECTION 2 - FILE INTEGRATION PLAN
Evaluate:
- data/support/support-data.json
- data/semantics/intent-semantics.json
- data/semantics/object-semantics.json
- data/semantics/context-semantics.json
- data/semantics/state-semantics.json
- application source code

For each use: [CHANGE], [NO CHANGE], [REVIEW REQUIRED], or [DEVELOPER ASSISTANCE REQUIRED].
Do not claim a semantic value already exists unless the current semantic files were supplied or explicitly confirmed.

SECTION 3 - STEP-BY-STEP ADDITION INSTRUCTIONS
Write for a non-developer. Explain where to add the JSON, how to keep the JSON array valid, which semantic files to check, how to add only genuinely new vocabulary, when not to modify source code, and when to ask a developer.

SECTION 4 - REVIEW CHECKLIST
Check approved source, invented steps, unique id, valid JSON, semantic values, keywords/phrases, secrets/sensitive information, and solution order.

SECTION 5 - TEST QUESTIONS
Provide 5 clear positive questions, 2 alternate wordings, 2 ambiguous questions, and 2 unrelated questions.

SECTION 6 - FINAL MAINTAINER SUMMARY
Summarize files to change, files not to change, review items, and whether developer assistance is required.

APPROVED IT SUPPORT DOCUMENTATION
Paste the approved procedure below this line:

Prompt: Validate before check-in

Use this after the topic has been generated or manually edited.

Review the proposed IT Support Chatbot topic before check-in.

Use the approved source material as the authority. Do not invent corrections.

Check required fields, semantic arrays, lowercase hyphenated id, JSON syntax, invented procedures/URLs/commands/policies/security instructions, keywords and phrases, solution accuracy/order, state usage, semantic values requiring review, and whether the change is data-only or needs a developer.

Return:
- PASS or REVIEW REQUIRED
- Problems found
- Exact corrections needed
- Files to check or change
- Suggested smoke tests

APPROVED SOURCE MATERIAL:
[paste source]

PROPOSED TOPIC JSON:
[paste JSON]

Expected output

The prompt should return proposed JSON, a file integration plan, non-developer instructions, a review checklist, test questions, and a final maintainer summary. If current semantic files were not supplied, existence checks should be marked REVIEW REQUIRED rather than guessed.

Maintenance versus development

Adding approved support knowledge is maintenance. Changing how the chatbot scores, routes, authenticates, integrates, or conducts conversations is application development.
