Conversation state and identity

Conversation state is keyed by conversationId, so simultaneous conversations keep their own miss counts, ambiguity counts, feedback state, and unresolved-question details. During local Agents Playground testing, unresolved records use user as the user value. In a future Teams deployment, the user value will come from the authenticated Teams environment.

Original and rephrased questions

The first unresolved question is preserved as originalQuestion. A later rephrase or final clarification is stored separately as rephrasedQuestion. The second message supplements the first instead of replacing it, giving IT more context for follow-up.

Bounded ambiguity

The chatbot asks for clarification once when more than one support topic remains plausible. If the next attempt is still ambiguous, it stops asking for more detail and offers to submit the problem for IT review. This prevents an endless clarification loop.

Helpfulness feedback

After a support answer is found, the chatbot asks whether it was helpful. A Yes response completes the flow. A No response preserves the question that produced the answer and asks the user to describe the problem another way. If the revised description still cannot be resolved, the chatbot can offer IT-review submission while retaining the original question.

Design principle

The chatbot should prefer asking for clarification over confidently returning the wrong support topic.
