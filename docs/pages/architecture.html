Architecture

What you'll find here: The main processing components that turn a user's message into a support result.

Matching model

The current design separates understanding into three conceptual signals:

SignalPurpose
IntentWhat the user is trying to do.
ObjectThe application, feature, device, or thing involved.
ContextAdditional details that help distinguish similar support topics.

Knowledge separation

Approved support content and semantic matching vocabulary are kept separate. Unresolved user submissions are also kept separate and must be reviewed before becoming approved support knowledge.

MVP boundary

The current milestone proves the core support workflow locally. Production Teams deployment, organizational authentication, Pub/Sub, automated weekly notifications, database-backed knowledge, and production monitoring remain outside the MVP.
