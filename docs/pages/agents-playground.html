LOCAL DEVELOPMENT

Testing Without Company Teams Access

What you'll find here: How Microsoft 365 Agents Playground lets developers exercise the local chatbot before they have access to an organization's Microsoft Teams environment.

Why this path exists

A developer does not need access to the company's Teams tenant to work on the current local MVP. Microsoft 365 Agents Playground can provide a local Teams-style interface for testing the chatbot's existing behavior.

No company Teams access

Run local testing with two terminals

Local testing uses two terminals at the same time. The first runs the chatbot application. The second runs Microsoft 365 Agents Playground.

Terminal 1 - Run the chatbot

Open Terminal 1 in the project root and start the chatbot:

npm run dev

Keep this terminal running. It provides the chatbot endpoint at http://localhost:3978/api/messages.

Terminal 2 - Run the chatbot testing page

Open Terminal 2 in the project root while Terminal 1 is still running:

agentsplayground -e http://localhost:3978/api/messages -c emulator
Terminal 1                         Terminal 2
Chatbot application               Microsoft 365 Agents Playground
       │                                      │
       └── http://localhost:3978/api/messages ┘
                                              ↓
                                   Chatbot testing page
Important: Do not stop Terminal 1 before starting Terminal 2. Agents Playground needs the running chatbot endpoint in order to send and receive test messages.

After both are running, use the scenarios in Sample Conversations as smoke tests.

What this can validate

  • Known support-topic matching
  • Intent / object / context / state behavior
  • Topic scoring
  • Bounded ambiguity and clarification
  • Rephrase flow
  • Unresolved issue handling, original/rephrased question preservation, and local user identity
  • Helpfulness feedback after a found solution

What still requires enterprise access later

  • Actual organizational Microsoft Teams deployment
  • Tenant-specific identity and permissions
  • Production authentication and authorization
  • Organization security review and production configuration
Local identity: During local Agents Playground testing, unresolved submissions use user as the user value. Production Teams identity is a later enterprise integration requirement.
Security warning: The current local development configuration uses dangerouslyAllowUnauthenticatedRequests: true. It is for local Agents Playground testing only and must not be carried into production.
